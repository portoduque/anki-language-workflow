# 06 — Decks, Tags, Browser, and Search

## Broad decks, fine-grained tags

Anki recommends broad deck categories rather than hundreds of tiny decks.

Reasons include:
- reduced contextual cueing;
- simpler navigation;
- better performance/maintainability;
- easier mixed review.

For this project:
- parent deck = target language;
- subdeck = trained skill;
- tags = linguistic/content metadata.

## Tags

Tags apply at the **note** level, so sibling cards share tags.

Use tags for:
- vocabulary;
- chunk;
- collocation;
- grammar;
- word-form;
- word-order;
- expression;
- minimal-pair;
- source/lesson;
- CEFR or other level when known.

Use flags when a marker should apply to a single card rather than all sibling cards.

## Browser

The Browser is the main interface for:
- searching;
- editing notes/cards;
- changing decks;
- changing note types;
- finding duplicates;
- suspending/unsuspending;
- setting due dates;
- inspecting card information.

## Search

Anki supports rich search syntax, including deck, tag, note type, card state, fields, dates, and combinations.

When the workflow needs to document a complex search, consult the current official Searching page rather than guessing syntax.

## Filtered decks

Filtered decks are temporary study views built from searches. They are appropriate for targeted study/cramming without permanently reorganizing the collection.
